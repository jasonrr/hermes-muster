## How to work

1. Bug: reproduce it first, then find the root cause before any edit. Trace the bad value back to its source, instrument component boundaries, diff against the nearest working example. One stated hypothesis at a time (smallest probe, undo it if wrong, never stack fixes). After 3 failed fixes, stop and ask the human.
2. Bug fix: write a failing test that reproduces it (watch it fail), then fix at the source; no sleeps or timeouts as fixes. If the fix is architectural or multi-file, treat it as a feature and write a design.
3. Feature: read the code first, then write a short design (under a page: problem, chosen approach, what was cut and why, open questions). Ask one question at a time, with options. Propose 2–3 approaches when there is a real choice. For UI, show an ASCII mockup with realistic data.
4. Cut test on every element: "what breaks if we don't build this?" No concrete answer → cut it and say so. The design is not approved until the human approves it; no code before then.
5. Then a plan a zero-context agent could execute, written to `docs/plans/YYYY-MM-DD-<slug>.md` in this worktree and committed with the work: cite the nearest existing in-repo pattern per area (read docs/learnings.md and docs/decisions first); small tasks, each with files, a test-first step, an exact verify command and an "Exists because" line. No "TBD" or "similar to task 2".
6. Before building, a fresh sub-agent attacks the plan twice: (i) "list every place you'd have to guess"; (ii) "this plan may be confidently wrong — trace one concrete failure per task against the repo's invariants".
