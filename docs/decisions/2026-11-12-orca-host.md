# Orca as an optional terminal host

## Problem

Muster runs every builder in herdr. Orca can host the same kind of run: a Claude Code CLI in a
visible terminal inside a git worktree. Muster should offer Orca as a choice alongside herdr, not as a
replacement. Every route must work on Orca: issue runs, ad-hoc runs, `hermes muster open` analysis
workspaces, holds and decisions that prompt the agent, and cleanup.

Muster talks to herdr directly, about 25 times across `launcher.py`, `cleanup.py`, `adhoc.py`, `hold.py` and
`decisions.py`. Claude Code hooks deliver every event, and they work on any host. herdr does six
jobs: worktree lifecycle, a tab with Claude started on muster's `--settings`, brief delivery with
proof, agent state, cleanup's quiet check, and analysis workspaces.

## Chosen approach

**A host seam.** A new `muster/hosts/` package holds `herdr.py`, which is today's calls moved as they are,
and `orca.py`. Both expose the same small set of functions and return the same normalized dicts:
worktree list/create/open/remove, open a terminal, start the agent, send a prompt with proof,
read agent state, take a quiet fingerprint, and open or close an analysis workspace. Callers stop
building herdr argv and call the seam instead. A new global `host: herdr|orca` setting, default `herdr`,
picks the host for new runs. Each launch and workspace record stores its `host`, so flipping the setting
never sends an in-flight run's calls to the wrong CLI.

How Orca does each job:

- **Worktrees:** `orca worktree create --repo path:<clone> --branch <b> --base-branch origin/<base> --setup inherit
  --no-parent`. Orca chooses the path, so muster records the path Orca returns. Crash recovery finds the
  worktree by branch in `orca worktree list`, which already works today. If the clone is not yet an Orca
  repo, muster runs `orca repo add --path <clone>` first. `remove` maps to `orca worktree rm`, which keeps
  the branch. The `worktrees` setting and the clone-name collision check apply to herdr only.
- **Terminal and agent:** `orca terminal create --worktree id:<wt> --command "<env> claude <launch_args>"`. This
  avoids `agent launch`, which cannot pass `--settings` or `--permission-mode`. `terminal set-pane-title <agent
  name>` gives the pane the identity that herdr agent names give today.
- **Identity across restarts:** the record keeps the worktree id, `ptyId` and pane title. A stale handle
  (`terminal_handle_stale`, or the handle missing from `terminal list`) is looked up again by pane title
  inside that worktree. It is never assumed gone.
- **Agent state:** `orca worktree ps --json` `agents[].state`, matched to the terminal by `paneKey` = `tabId:leafId`.
  It is mapped to muster's `idle | working | blocked | done`.
- **Prompt with proof:** `orca terminal send --enter --wait-submit 30`. A `turn_started` stage means delivered.
  `agent_prompt_blocked` means not sent, which maps to today's readiness failure. Anything else falls back
  to the hook evidence (`launcher.seen`), as the herdr path does. Orca has no `completion_seq`, so that
  branch of `delivered()` exists for herdr only.
- **Quiet:** every agent's state is idle or done, plus a hash of each terminal's `terminal read --screen` output,
  plus a process scan. Orca exposes no shell pid, so the scan uses processes whose cwd is inside the worktree
  (`lsof -d cwd`), minus `QUIET`, helpers and the agent itself. Unlike herdr's shell-tree walk, this also
  catches jobs detached with nohup.
- **Analysis workspaces:** `orca repo add --kind folder`, then one terminal. To close one: `terminal close --all`,
  then `worktree rm folder:<id>`. Orca forgets the folder and leaves the files on disk.

**Testing:** a `tests/fake_orca.py` beside `fake_herdr.py`. The existing launch, cleanup, hold and decisions tests
run on both hosts. Acceptance adds one Orca issue run.

Rejected: an Orca shim that fakes herdr's JSON shape. It would invent `shell_pid` and the seq counters, and
the gaps would fail silently. Also rejected: copying the launcher and cleanup for Orca, which would duplicate
about 100 KB of logic.

## Cut and why

- **A host setting per repo:** nothing concrete breaks with one global choice.
- **Orca chat surface:** chat sessions don't run muster's hooks or settings. Terminal only.
- **Orca orchestration (mailboxes, task DAGs):** Hermes is muster's coordinator (AGENTS.md).
- **Starting Orca automatically:** if the runtime is unreachable, the launch fails as `setup` with a message
  saying "start Orca". herdr runs behave the same way when herdr is down.
- **Paired or remote Orca environments:** local only. `--environment` can come later.
- **Moving a live run between hosts:** the record pins the host.
- **Other agents (Codex and others):** unchanged scope. Muster stays Claude only.

## Open questions

These are answered by a live spike, the build's first task, before any Orca code. None of them changes the approach.

1. **Orca's agent-state values:** what Orca reports at a permission dialog and at a finished turn, and so the exact
   mapping to idle, working, blocked and done.
2. **Restarts:** whether the pane title and `ptyId` survive an Orca restart, so the lookup can find the pane again.
3. **An existing branch:** `worktree create --branch` gives a taken name a numeric suffix. Muster's `--adopt` and
   fast-forward paths need it to use the existing branch. If Orca won't, the fallback is `git worktree add` and
   `repo set --external-worktree-visibility show` for that case only.
4. **Repo default tabs:** whether Orca's setup hooks or default tabs add terminals that the quiet check must allow.
